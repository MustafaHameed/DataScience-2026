\chapter{Glossary}\label{app:glossary}

\normalfigures

Every term the chapters mark with \term{emphasis}, with the chapter that
defines it.

\newcommand{\gt}[3]{\textbf{#1}~{\small\textit{(Ch.~#2)}} --- #3\par\smallskip}

\begin{multicols}{2}
\small

\gt{Attestation}{21}{A guest proving to a remote party what it is --- which
hardware, firmware and image --- before that party releases a key or data.
Without it, memory encryption protects nothing useful.}

\gt{Auto-convergence}{17}{Deliberately throttling a guest's vCPUs during live
migration so that its dirty rate falls below the transfer rate. Buying
convergence with the guest's performance.}

\gt{Ballooning}{6}{A driver inside the guest allocates memory and tells the
hypervisor it may take those pages, so the \emph{guest} chooses what to give
up. Requires guest cooperation.}

\gt{Binary translation}{3}{Rewriting a guest kernel's instructions before they
execute, replacing the ones the processor will not trap. VMware's answer to the
non-virtualizability of x86.}

\gt{Blast radius}{19}{How much of an estate one successful attack reaches. A
more useful ranking than a severity score.}

\gt{Boot storm}{15}{Many virtual desktops starting at once, demanding several
times the all-day storage IOPS for a few minutes. What VDI sizing must be based
on.}

\gt{cgroup}{8}{Control group. A kernel mechanism bounding a process tree's CPU,
memory, I/O and process count. CPU limits throttle; memory limits kill.}

\gt{cloud-init}{16}{Software that runs on a guest's first boot and applies
per-instance configuration from the platform's metadata service. What makes one
golden image usable everywhere.}

\gt{Co-stop}{6}{Time a wide guest waits because its own vCPUs cannot all be
scheduled together. The cost of relaxed co-scheduling.}

\gt{Confidential computing}{21}{Running a workload on hardware whose operator
cannot read it: encrypted memory, protected registers and attestation.}

\gt{Consolidation ratio}{1}{Guests per host. The headline number of a
consolidation, and also its concentration of risk.}

\gt{Container}{8}{Processes on a shared kernel given a private view by
namespaces and a bounded share by cgroups. Not a virtual machine; still
virtualization.}

\gt{Control loop}{10}{Read desired state, observe actual state, take one step
to reduce the difference, repeat. The single idea Kubernetes is built from.}

\gt{Copy-on-write}{12}{Writing a changed block to a new location rather than
over the original, so the original can still be read. The basis of snapshots,
linked clones and overlayfs.}

\gt{CRUSH}{12}{Ceph's deterministic placement function: any client computes
where data lives rather than looking it up, which is what lets it scale.}

\gt{Dirty rate}{17}{How fast a running guest modifies its own memory. Live
migration converges only if it is below the transfer rate.}

\gt{Digest}{9}{The SHA-256 of an image's contents. Identity and integrity in
one. A \emph{tag} is neither.}

\gt{Discard / TRIM}{12}{Telling the storage layer that blocks freed inside a
guest are no longer needed. Without it, deleting files returns nothing to a thin
pool.}

\gt{DPU}{20}{A card with its own processors that runs the virtual switch,
storage path and encryption, returning host cores to guests and placing the
infrastructure outside the hypervisor's control.}

\gt{Egress}{14}{Data leaving a cloud, charged per gigabyte while ingress is
free. The economic shape of lock-in.}

\gt{Encapsulation}{1}{A running machine as a file --- copyable, versionable,
restorable. The motive with no physical equivalent.}

\gt{Erasure coding}{12}{Storing $k$ data and $m$ parity chunks instead of
replicas. More usable capacity, more write latency. For archives, not
databases.}

\gt{Extended page tables}{4}{Hardware translation of guest-physical to
host-physical addresses. 24 memory accesses per TLB miss, and no VM exit per
guest page-table edit --- which is why they beat shadow paging.}

\gt{Fencing}{17}{Forcibly powering off a host believed to have failed, before
restarting its guests elsewhere. Without it, a network partition produces split
brain and corruption.}

\gt{Firecracker}{11}{A 50{,}000-line VMM with a minimal device model: a guest
boots in about 125 ms with under 5 MB of overhead. What AWS Lambda runs in.}

\gt{gVisor}{11}{A sandbox implementing most of the Linux system-call interface
in user space, cutting the host's exposed calls from about 350 to about 60.}

\gt{High availability}{17}{Restarting a failed host's guests elsewhere. The
guests crash and reboot; memory is lost. Distinct from fault tolerance.}

\gt{Hypervisor}{1}{The software that creates and maintains virtual machines.
Used interchangeably with \emph{virtual machine monitor}.}

\gt{Idempotent}{16}{Applying the same definition twice changes nothing the
second time. What makes infrastructure as code safe to run on a schedule.}

\gt{IOMMU}{4}{A memory management unit between devices and memory, translating
and confining DMA. Without it, device passthrough gives a guest all of physical
memory.}

\gt{Kata Containers}{11}{An OCI runtime that gives every Pod its own
lightweight virtual machine, selectable per workload with RuntimeClass.}

\gt{Linked clone}{15}{A desktop sharing a read-only base image with a small
private delta. The 20:1 capacity saving that makes non-persistent VDI
affordable.}

\gt{Live migration}{17}{Moving a running guest between hosts with a pause its
users cannot perceive. The capability that makes patching and rebalancing
routine.}

\gt{MIG}{20}{Multi-instance GPU. Hardware partitioning of memory \emph{and}
compute into independent instances, in fixed profiles. Density with a
guarantee.}

\gt{MicroVM}{11}{A virtual machine with no firmware, no PCI bus and no legacy
devices --- the cost was compatibility, not virtualization.}

\gt{MTU}{13}{The largest frame a link carries. An overlay's encapsulation
reduces the usable inner MTU, and ignoring that produces hangs rather than
errors.}

\gt{Namespace}{8}{A kernel mechanism giving a process group its own instance of
a global resource: mount points, process IDs, network interfaces, users and
four more.}

\gt{NUMA}{6}{Non-uniform memory access. Memory attached to one socket is
reached more slowly from another. Decided at provisioning time, not tunable
afterwards.}

\gt{Overcommit ratio}{6}{Allocated resource divided by physical resource.
Meaningless for memory without an \emph{active} figure beside it.}

\gt{Overlay (network)}{13}{A virtual network carried inside ordinary IP
packets, so it crosses any routed path. VXLAN's 24-bit identifier replaces the
VLAN's 12.}

\gt{Overlayfs}{8}{Read-only layers stacked under one writable layer, with
copy-up on write. Why many containers from one image cost little more than
one.}

\gt{Paravirtualization}{2}{Modifying the guest so it cooperates with the
hypervisor rather than being deceived by it. Fast, simple, and it needs the
guest's source.}

\gt{Passthrough}{7}{Assigning a physical device to one guest. Native speed, and
no live migration, no memory overcommit and no hardware independence.}

\gt{Pod}{10}{Kubernetes' unit of scheduling and of IP address: containers that
must share a node and a lifetime.}

\gt{Popek--Goldberg condition}{3}{A monitor can be built by trap-and-emulate if
the sensitive instructions are a subset of the privileged ones. x86 failed it
for twenty-five years.}

\gt{Post-copy}{17}{Switching the guest over first and fetching pages on demand.
Always terminates; loses the guest if the network fails mid-transfer.}

\gt{Pre-copy}{17}{Copying memory in rounds while the guest runs, then pausing
briefly for the remainder. The standard live-migration algorithm.}

\gt{Privileged instruction}{3}{One the hardware traps in user mode. A property
of the processor, unlike \emph{sensitive}.}

\gt{Quorum}{17}{A majority of cluster votes, required before acting. Why
clusters have odd membership or a witness.}

\gt{Ready time (\%RDY)}{6}{The fraction of time a vCPU was runnable and not
scheduled. Visible inside the guest as steal time, and the single most useful
capacity number there is.}

\gt{Reconciliation}{10}{Continuously reducing the difference between desired
and actual state. Why failure recovery in Kubernetes is ordinary behaviour
rather than a feature.}

\gt{Request / limit}{10}{A request is reserved by the scheduler whether used or
not; a limit is enforced by cgroups. Confusing them is the commonest source of
Kubernetes capacity trouble.}

\gt{RPO / RTO}{17}{How much data you may lose, and how long you may be down.
Independent, and they cost differently.}

\gt{Sensitive instruction}{3}{One the monitor must know about --- it changes
the configuration, or its result depends on it. A property of what the monitor
needs.}

\gt{SEV-SNP}{21}{AMD's confidential VM technology: encrypted memory plus
integrity protection against page remapping and replay.}

\gt{Side channel}{19}{Inferring another guest's data from shared hardware
timing. Not a software fault, so not fixable by patching alone.}

\gt{Split brain}{17}{Both sides of a partitioned cluster believing the other
failed, and both running the same guest. Produces corruption, not downtime.}

\gt{SR-IOV}{7}{A PCIe device presenting itself as many virtual functions, each
assignable to a guest. Line rate with no host CPU, and no live migration.}

\gt{State file}{16}{Terraform's record of which real objects it created.
Authoritative, holds secrets, and must be remote and locked.}

\gt{TDX}{21}{Intel's confidential VM technology: a \emph{trust domain} with
encrypted memory and integrity protection, designed with both from the start.}

\gt{TEE}{21}{Trusted execution environment. A context protected from everything
outside it, including the hypervisor and the operator.}

\gt{Thin provisioning}{12}{Allocating storage only as it is written. Memory
overcommit for disks: usually a large saving, occasionally a cliff.}

\gt{Trap-and-emulate}{3}{Running the guest unprivileged and emulating what the
hardware traps. Sound only where the Popek--Goldberg condition holds.}

\gt{Trusted computing base}{5}{All the code that can compromise the host.
ESXi's is about 150 MB, Xen's hypervisor about 1 MB, KVM's the whole Linux
kernel.}

\gt{Type-1 / Type-2}{2}{Whether the hypervisor needs another operating system's
permission to reach the hardware. KVM fits neither label cleanly, which is a
fact about the labels.}

\gt{Utilisation vs saturation}{18}{Fully used is not the same as queueing. Only
the second is felt by users, and most dashboards show only the first.}

\gt{vCPU}{6}{A virtual processor: a thread the hypervisor schedules onto a
physical core.}

\gt{VDI}{15}{Virtual desktop infrastructure. The desktop runs in the data
centre; pixels go out and keystrokes come back. Latency, not bandwidth, is what
users feel.}

\gt{VFIO}{7}{The Linux framework for assigning a device to a guest safely,
using the IOMMU.}

\gt{vGPU}{20}{Splitting a GPU's memory between guests and time-slicing its
compute. Density without a performance guarantee.}

\gt{virtio}{7}{The standard paravirtual device interface: a split driver around
a shared virtqueue, with one exit per batch instead of per register access.}

\gt{Virtqueue}{7}{Three rings in shared memory --- descriptors, available,
used --- through which a virtio front end and back end exchange work.}

\gt{Virtual machine}{1}{A complete computer implemented in software, on which
an unmodified operating system can be installed.}

\gt{Virtualization}{1}{Inserting a layer that presents a resource differing
from the physical one, while preserving the interface above it. It multiplexes,
aggregates or abstracts.}

\gt{VMCS}{4}{The per-vCPU structure holding guest state, host state, the
controls deciding what causes a VM exit, and the exit information.}

\gt{VM escape}{19}{Code in a guest gaining execution on the host. Overwhelmingly
found in device models rather than in the hypervisor core.}

\gt{VM exit}{4}{A hardware transition from guest to hypervisor. A world switch
of several hundred cycles, not a function call.}

\gt{VNI}{13}{A VXLAN network identifier: 24 bits, so about 16.7 million virtual
networks.}

\gt{VPID}{4}{A tag on TLB entries identifying the virtual CPU they belong to,
so they survive a VM transition instead of being flushed.}

\gt{VT-x / AMD-V}{4}{The processor extensions that made x86 satisfy the
Popek--Goldberg condition, by adding an operating mode rather than changing any
instruction.}

\gt{VXLAN}{13}{An overlay encapsulating a guest's whole Ethernet frame in UDP,
at a cost of 50 bytes on an IPv4 underlay.}

\end{multicols}
